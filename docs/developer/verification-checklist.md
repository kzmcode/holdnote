# 実機検証チェックリスト

単体テスト（`make test`）と配布物の自動チェック（`make verify`）では確認できない、実機・実サービスが必要な項目です。
結果に応じて該当モジュールを調整してください。

> 次の項目は自動化済みのため、このリストから外しています：署名・entitlement・Info.plist、同梱ライブラリの参照先、ライセンスファイル、whisper-cli の起動とフラグ（`make verify --transcribe`）。
> 利用環境の状態は `holdnote --doctor` で確認できます。

## 録音・ホットキー（`src/hotkey.rs`, `src/recorder.rs`, `src/app.rs`）

- [ ] Finder / Chrome / VS Code 前面で `⌃⌥R` 長押し → 録音開始、離すと停止。前面アプリに文字が入力されない（AT-01）
- [ ] `R` を先に離す／`Control` を先に離す の両順序で録音が止まる。二重録音しない（AT-02, REC-04）
  - 修飾キーを先に離した場合は 100ms 周期のキー状態ポーリング（2 回連続で未押下）で停止する実装です
- [ ] 押下から 300ms 以内にオーバーレイ表示、解放から 200ms 以内に停止（NFR-01/02）
- [ ] 0.3 秒未満・無音は破棄され「破棄しました」と表示される
- [ ] 既定の入力が仮想デバイス（BlackHole 等）のとき「音声が入力されていません（入力: …）」と表示される
- [ ] 入力監視を許可していない状態で、ホットキーを押し続けている間は録音が継続する
- [ ] 録音中のスリープ・画面ロック・マイク抜去で安全に停止（AT-05）
  - cpal はデバイス切替もエラーとして通知するため、既定デバイス変更で録音が止まりすぎる場合は `recorder.rs` のエラーコールバックで種類を絞る
- [ ] 44.1kHz / 48kHz の入力デバイスで 16kHz WAV が正しく生成される
- [ ] 文字起こし中に次の録音ができ、別ファイルになる（AT-07）
- [ ] 他アプリと衝突するホットキーに変更すると、エラー表示され以前のキーが維持される（REC-05）
- [ ] 待機中 CPU 1% 未満・メモリ 100MB 未満（NFR-03/04、アクティビティモニタで確認）

## Google Drive API（`src/storage/`）

- [ ] 接続 → Picker でフォルダ選択 → 保存テスト成功（AT-11）
- [ ] 録音 → 選択フォルダに `.md` が 1 件作成され、履歴の「開く」で Drive が開く
- [ ] オフラインで 3 件録音 → 復帰後に 3 件が重複なく保存（AT-12）。再送間隔は 30 秒から倍々、最大 30 分
- [ ] トークン失効（連携解除や Google 側でアクセス削除）→「保存できませんでした」→ 再認証後に「すべて再試行」で送信（AT-13）
- [ ] アップロード直後に通信断 → 再試行時に `appProperties.holdnoteJobId` で既存ファイルを検出し重複しない（AT-14）
- [ ] 保存先フォルダを削除 → 要対応 → フォルダ再選択 → 再試行で新フォルダに保存（API-10）
- [ ] 保存先変更後も、未完了ジョブは作成時のフォルダへ送られる（AT-15）
- [ ] OAuth 同意画面が「テスト中」の場合、7 日後に再認証が必要になることを利用者に周知

## 障害回復

- [ ] 録音中・保存直前に `kill -9` → 再起動後に復旧（AT-16）。録音中の WAV はヘッダ修復して処理継続
- [ ] 保存成功後 24 時間で音声が削除され、未完了ジョブの音声は残る

## 配布

- [ ] **Homebrew の入っていない** 別の Mac で `brew` 導入 → Gatekeeper 許可 → マイク許可 → 録音・文字起こし・保存できる（AT-18。同梱 whisper-cli の最終確認を兼ねる）
- [ ] `brew upgrade --cask` 後に設定・履歴維持（AT-19）
- [ ] Finder のアイコンが外側透明、メニューバー アイコンがライト/ダーク双方で判別可能（AT-25）
